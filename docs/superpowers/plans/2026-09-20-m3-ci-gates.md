## Task 3：依赖差异与已知公告检查

**Files:** check-dependency-delta.mjs；ci-gates.test.mjs；ci.yml；check-supply-chain.mjs。

**接口：** 导出 `compareLocks(base,head)` → `{added,removed,changed}`，每项包含 lock path、name、old/new version、license、resolved、integrity；`classifyAudit({status,signal,report})` → `{state,exitCode}`。CLI 只从受约束 GitHub event JSON 读取 base/head，不接受 shell 命令或任意审计 endpoint。

- [ ] 先测试同版本但完整性改变也必须列为 changed，不能只比较版本号：

```js
const entry = {version:'1.0.0',resolved:'https://registry.npmjs.org/pkg/-/pkg-1.0.0.tgz',integrity:'sha512-AA==',license:'MIT'};
const base = {packages:{'node_modules/pkg':entry}};
const head = {packages:{'node_modules/pkg':{...entry,integrity:'sha512-BB=='}}};
assert.equal(compareLocks(base,head).changed.length, 1);
assert.equal(classifyAudit({status:1,signal:null,report:{error:{code:'ENETUNREACH'}}}).state, 'BLOCKED');
assert.equal(classifyAudit({status:0,signal:null,report:{}}).state, 'BLOCKED');
```

以上简短 integrity 仅用于纯 diff 单测，不送 supply validator；真实 lock 的格式验证沿用现有完整 SRI 校验。

- [ ] Git 输入契约：PR 取 event.pull_request.base.sha/head.sha，merge_group 取其 base_sha/head_sha，普通 push 取 before/after；SHA 必须 40 位 hex、对象存在且共同历史可证。新分支 push 的 before 为全零时，使用本次 checkout 获取的准确 origin/master 并在报告标注 baselineKind；缺历史不得退回空 lock。手动 dispatch 使用实际 origin/master/HEAD，禁止把 `HEAD^` 猜作 PR base。
- [ ] 使用 `execFileSync('git',['show',sha+':package-lock.json'],{maxBuffer:8*1024*1024,timeout:10000})` 等固定参数读取 base/head manifest；不切换目录、不导入或执行 base/head 的 JS。解析两个 lock，导入现有 `validatePackageLock(lockfile, packageJson, policy)`（tools/check-supply-chain.mjs:137），分别传入同一 SHA 的 package.json 与 lock，使用已审阅的当前 policy 校验。旧 license policy 不当成新 policy 白名单。base 不满足当前 policy 应分类历史输入/策略变化阻塞，不能伪装新增漏洞。
- [ ] 将仅含两个 JSON 输入的副本写入 `mkdtemp` 创建的本 job 审计目录；不要使用来自 PR 的任意 .npmrc，固定 npm registry 和 ignore-scripts。manifest 只作数据，不运行 scripts。隔离目录没有 node_modules，也不执行 npm install/ci。固定执行：

```bash
npm audit --package-lock-only --include=dev --include=optional --ignore-scripts --audit-level=high --json --registry=https://registry.npmjs.org/
```

包装层捕获返回值与有界 JSON，不使用 `|| true`。保留 high/critical 阈值：有效完整结果且二者均为 0 才可能 PASS；存在 high/critical → FAIL；网络错误、error 字段、缺 metadata/vulnerabilities、异常 schema、signal/timeout/输出截断/未知非零 → BLOCKED。moderate/low 明确列出并保留既有 SLA，不声称零漏洞。审计库随时间变化，结果必须包含查询时间与 registry。

- [ ] 新 `dependency-delta-audit` job 使用 ubuntu-24.04、contents:read、完整 fetch 的 checkout、批准 Node/npm、环境准入、`npm ci --ignore-scripts` 后运行 `npm run supply:check` 与 `node tools/ci/check-dependency-delta.mjs`。head 审计在隔离数据目录进行，CI 源目录不被切换。保留原 Linux audit:dependencies，不以这个新 job 省略它。
- [ ] 负向测试覆盖新增/删除/升级、同版本 source/SRI/license 改变、缺 base 对象、拒绝错误 registry/license/integrity、网络不可用、high/critical 命中、空 JSON/缺字段、超时、源目录前后不变；`node --test test/ci-gates.test.mjs test/supply-chain.test.mjs`。
