# AlphaForge M3 Protocol Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Execute inline with `executing-plans`; repository instructions prohibit delegation. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the first local, fully tested AlphaForge protocol loop for fixed-supply Strategy Pass custody, bounded owner authorization, per-swap risk permits, and real ERC-20 settlement through a fixed B2 Test Venue.

**Architecture:** Each strategy has one freely transferable fixed-supply ERC-20 Pass. An immutable owner Vault deploys its own PassLocker, pins one SwapAdapter, and accepts only a typed spot-swap action covered by one active owner authorization and a one-use risk permit. The adapter pins a deterministic finite-liquidity Test Venue; there is no arbitrary call path, proxy, upgrade hook, native-value path, or privileged withdrawal.

**Tech Stack:** Solidity 0.8.31, OpenZeppelin Contracts 5.4.0 derived pragma-pinned subset, Foundry 1.5.1, Slither 0.11.3, Node 24.21.0, npm 11.19.1.

## Global Constraints

- Canonical repository is `pdbsy/quantpass-arbitrum-hackathon`; branch is `02/protocol-m3` from `7ecba357d5a19f387e86f578822af04a6261fed2` or a later verified `origin/master`.
- Robinhood Chain Testnet chain ID is `46630`; this plan authorizes local implementation and validation only.
- Never deploy, sign with non-test keys, broadcast, use real funds, enable mainnet, merge, force-push, or relax required checks.
- Strategy Pass is a freely transferable fractional ERC-20 with creator-defined constructor supply, no mint after construction, no admin, blacklist, freeze, proxy, or upgrade path.
- Pass market price never enters capacity. Strategy Pass uses 18 decimals; one whole Pass (`1e18`) supplies one whole AF-USDC (`1e6`) of principal capacity, so one AF-USDC base unit consumes `1e12` Pass base units.
- Deposits lock Pass; profit does not require Pass; profit withdrawal does not unlock Pass; principal withdrawal unlocks Pass; loss alone does not unlock Pass; full close releases all remaining Pass.
- Owner registers one bounded EIP-712 strategy authorization. Each swap needs a separate EIP-712 risk permit. M3 accepts EOA signatures only.
- Vault, PassLocker, adapter, venue, assets, owner, risk signer, pause guardian, strategy identity, and policy-critical configuration are immutable where applicable.
- Pause is irreversible for a Vault address. It blocks deposits and executions while preserving owner revoke, withdraw, close, and final Pass release.
- The only execution primitive is a typed spot swap. No arbitrary target, calldata, selector, token transfer, delegatecall, or native value is exposed.
- Every external token/venue mutation is guarded against reentrancy. Exact approvals are reset to zero after use.
- Multi-asset partial-withdrawal accounting is gated by the Decision Request sent to Macbeth01 on 2026-09-14. Tasks 1-4 and 6-8 may proceed without changing that semantic; Task 5 must use the approved option.
- Every production behavior begins with a focused failing test whose failure is observed and recorded before implementation.
