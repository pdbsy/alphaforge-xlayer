1. 部分上链
链上负责 Pass 供应、所有权、转让、策略绑定、Vault 托管、
本金/容量、锁定解锁、权限和资金结算。
账户资料、搜索、图表、论坛、排行榜、索引和策略计算保持链下。
链下账户、数据库和 UI 状态不能授予资产操作权限。

2. Strategy Pass
Creator 定义固定供应，发行后不得增发。
Pass 可分割、可转让。
1 PASS 对应 1 AF-USDC 本金容量，不是 1 AF-USDC 的交易价格。
不要擅自更换现有代币标准、重定义权益或引入新收费机制。

3. 精度
AF-USDC 6 decimals，Pass 18 decimals。
usdcRaw → passRaw：乘以 10^12。
passRaw → usdcRaw：必须整除 10^12，否则拒绝。
禁止截断、暗中舍入和隐藏 dust。
此限制用于本金/容量换算，不得错误限制普通 Pass 转账的
完整 18 位精度。
本金、容量和可提本金等优先使用 AF-USDC 的整数基本单位。

4. Vault 身份与权限
创建时显式指定非零且不可变的 Owner。
Owner 与 strategy creator 是不同语义角色，地址可以相同。
不能默认让 deployer、factory 管理员或 msg.sender 获得 Owner 权限。
本阶段不做 Owner 迁移、隐含升级权限或代签授权。
deposit / withdraw / close 由 Owner 直接授权，结算给 Owner。

5. 本金、利润和 Pass
存入本金锁定对应 Pass。
利润不额外占用 Pass，提取利润不释放 Pass。
提款遵循已冻结的利润优先及本金核算规则。
提取本金按对应容量释放 Pass。
亏损不自动解锁 Pass。
Full close 按规则释放剩余 Pass，不要求用户补足亏损。

6. 持仓与外来资产
已记账的非 USDC 投资持仓约束本金退出，
full close 前必须按协议完成结算。
锁定的 Pass 是容量抵押，不是阻塞退出的投资持仓。
外部转入、未记账的 token/native dust 不影响本金、利润、
容量或 Pass 解锁，也不得阻塞正常退出。

7. Close 与 rescue
close 只处理协议已记账资产与状态。
不能枚举任意外部代币，也不能因为陌生 token 转账失败而无法关闭。
关闭后 Owner 通过独立 rescue 操作处理未保留的 excess。
必须按每种资产自身 raw units 计算 actual-minus-reserved。
rescue 失败不能撤销已经完成的 close。

8. 身份模型
AlphaForge Account 与钱包身份分离，兼容未来关联多个钱包。
资产操作以钱包签名和合约权限为准。
本阶段不自动扩展为完整账户登录、钱包绑定平台。

9. 链确认与恢复
softReadyDepth 默认 3，reorgSearchLimit 默认 128，可配置。
它们不是 L1 finality 承诺。
交易哈希、receipt success、索引完成、产品可用状态分别建模。
浏览器提供的状态不能作为链上成功的权威。

10. 退出不依赖平台健康
索引/API degraded 时不能展示陈旧数据为 READY。
但在链身份、合约状态、Owner 和退出条件可验证的前提下，
不得仅因平台 API 或索引不可用而剥夺 Owner 直接退出能力。

11. 策略执行暂缓
不实现完整策略运行时、自动交易或 arbitrary execution。
不得为了演示收益，向生产 ABI 加入可随意伪造盈亏的接口。
测试 Harness 和模拟收益必须与真实产品路径明确隔离。
