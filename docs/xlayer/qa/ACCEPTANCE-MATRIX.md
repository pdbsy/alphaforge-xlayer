## Reproduced gap XLQA-MANIFEST-01

At the imported baseline, `packages/chain-adapter/src/manifest.ts` types describe Robinhood only, but runtime validation merely compares document fields with the caller's expected fields. JavaScript/parsed external configuration can supply an unsupported pair to both sides; recomputing the document digest makes it pass. This violates the new migration specification's explicit supported-pair requirement. It is not evidence of remote exploitability: the expectation must originate in a trusted configuration path, and the imported composition still supplies a fixed Robinhood expectation.

The fix belongs in the adapter's runtime trust-pair admission, preserving the trusted digest/address checks. Do not broaden acceptance to arbitrary string/number pairs just to make the X Layer positive fixture pass. The five negative tests must pass after integration, without editing expected outcomes.

## Integration protocol

QA source stays branched from imported master. Manager foundation files may be copied only into a disposable test copy with their exact source/blob identity recorded; such an overlay is not a named combined candidate and does not transfer authorship. Final combined runtime and C/R/S evidence must bind the actual manager integration SHA. The test uses no fetch/HTTP listener and all wallet/RPC providers are local in-memory fixtures.
