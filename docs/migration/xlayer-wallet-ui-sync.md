# XLayer wallet UI synchronization

The user requested synchronization of Macbeth01's Robinhood account UI on 2026-09-26. The source is commit `7fcd844947390ed99d68d1d707099fd113b191da` on `macbeth01/account-wallet-eth`, including the account layout, expandable Pass holdings and Trade diagnostics cleanup. The exact source history is retained under `codex/reference-robinhood-ui-7fcd844` and the archive tag `archive/robinhood-ui-7fcd844`; the original commits and authors are unchanged.

The XLayer adaptation reuses the account header, compact wallet address with full-address title, native balance card, Pass cards and responsive layout. Its own wallet adapter continues to verify XLayer Testnet 1952 and native OKB. Existing deployed Vault interfaces retain USDT as their contract asset. Vault operations remain available through an explicit disclosure on the Trade page.

The separate preview build keeps its own simulated account and the existing Pass exchange ledger. It starts with 1,000 OKB and two Trend Passes. The user-selected fixed preview rate, 1 OKB = 120 USDT, supplies the displayed USDT estimate; it is not a live market price. The user-provided Strategy funds layout uses a nested simulated USDT balance in the same exchange state and storage key, starting with 10,000 USDT. One Pass provides one USDT of capacity; deposits freeze it and withdrawals release it. This USDT balance is a separate simulated asset from the native OKB balance and its displayed estimate. There is no automatic conversion or deployed funding operation. Earlier preview OKB allocations are returned in OKB during migration, with their records retained. The Robinhood-specific ETH conversion and USDC denomination are not imported.

The preview has no wallet provider, signature or broadcast path. The public build omits its entry module and keeps local finance disabled even when a preview flag is also present. Source provenance records retain every prior artifact revision and bind the adapted prototype to an exact reviewed source commit. Validation results are recorded by the existing source/manifest/snapshot workflow, not asserted by this migration note.
